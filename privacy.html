Privacy summary. ASAP is an offline-first personal expense and money manager. Financial accounts, transactions, budgets, imported documents and SMS-derived review candidates are processed locally on your device. ASAP does not operate a financial-data backend or require an account. The bundled Google ML Kit component may independently send limited technical diagnostics and device/app information to Google, as explained below.

1. Who operates the app?

This policy applies to ASAP: Expense & Money Manager (Android package com.asap.expensetracker), offered by Aditi Apps Worlds. For privacy inquiries, contact aditi.piyush948@gmail.com.

2. Information processed on your phone

  • Financial information: accounts, balances, transactions, transfers, refunds, credit cards, budgets, reminders, merchant names, notes and financial audit history are stored in an on-device SQLite database. The app does not upload this financial ledger to a developer server.
  • Bank statements and documents: PDFs, CSVs and user-selected email archive files may be imported using the device document picker and processed locally. Imported candidates require user review before posting to the financial ledger.
  • Receipt images: a user may select or capture images for local receipt processing. The text recognition feature uses bundled, on-device Google ML Kit models; the receipt image itself is not intentionally uploaded to a developer or cloud OCR server.
  • Optional voice entry: on supported Android versions, this feature uses an available on-device speech recognizer. The app does not store recorded audio files. Voice entry remains optional.
  • Optional App Lock: PIN-based protection stores a salted password-derived verifier, not the plaintext PIN. Android biometric authentication is performed through system interfaces; the app does not collect biometric templates.

3. Financial SMS detection (approval-gated feature)

ASAP has a standard Android build and a separate Google Play SMS-review build. The standard build does not request READ_SMS or RECEIVE_SMS. The SMS-review build is designed for optional, consent-based financial SMS detection and is not authorized for public release until Google Play's applicable permission review is completed.

Where this feature is lawfully enabled, the user must opt in and grant Android permission. The app examines incoming inbox entries locally after the consent boundary, identifies candidate financial alerts, and places them in a review queue. It does not automatically post detected events to the ledger or send SMS contents to the developer. The user can opt out or revoke permission. SMS content is not included in normal cloud auto-backup.

4. Data collected by third-party components

The bundled Google ML Kit text recognition software may send technical diagnostics and usage information to Google over encrypted connections. Google's published Android ML Kit disclosure describes information such as device manufacturer/model and OS version, app package/version, a per-installation identifier, performance and error metrics, and API configuration or input metadata. These technical data are separate from your financial ledger and receipt-image contents. Google states in its ML Kit disclosure that it does not transfer this diagnostic data to third parties.

See Google's ML Kit data disclosure for more detail. The app does not currently include an advertising SDK, a developer-operated analytics SDK, or an account-based cloud-sync backend. Any future features that materially change data handling will require a policy and Google Play Data Safety update.

5. Android permissions and user choices

  • Notifications: optional for reminders and applicable review notifications; messages avoid exposing sensitive financial information on the lock screen.
  • Microphone: requested only for optional voice entry.
  • Biometric authentication: optional, via the Android system when App Lock is enabled.
  • SMS read/receive: restricted to the separate approval-gated SMS review build, and not granted by default.
  • Internet/network state: may appear in the installed app because Google's ML Kit diagnostic transport uses them; no developer financial-data server is used.
  • Boot and background operation: used for bounded local reminder and, if enabled, SMS recovery tasks, subject to Android restrictions.

6. Storage, backups and security

Your local data is held in the Android application sandbox. Financial events use a local auditable ledger, and optional App Lock can restrict app access. Users can export encrypted local backups (.etbak) protected using AES-256-GCM with a user-selected passphrase. The app has no built-in online backup or mandatory login in this release.

If you manually export an encrypted backup or report to device storage, email, or a cloud destination selected through Android's picker, copies outside ASAP's private storage are managed by you and the destination provider. The app excludes its private financial database, receipts, PIN-related settings and SMS consent state from Android automatic cloud backup and phone-to-phone transfer.

7. Retention and deletion

Local records remain on the device until the user deletes them, clears app storage, or uninstalls the app. To delete local data, open Settings → Privacy & Data → Wipe All Local Data, complete any required App Lock verification, and confirm deletion. The wipe removes local financial records and supported private app files. Some manually exported backups/reports and copies in other applications or cloud services are outside the wipe's scope.

Google ML Kit technical diagnostics sent to Google are not held in ASAP's local ledger, and an ASAP local-data wipe cannot remove them from Google's systems. For detailed instructions and limitations, see Data Deletion and Requests.

8. Children, advertising, and payments

ASAP's intended audience is adults. This release does not contain advertisements or sell core financial features. The app does not initiate bank transfers or payments. Users should review financial candidates before approving any transaction.
